# My Collection

一个很轻、完全本地运行的视觉书签管理器。它把网页链接显示成电影海报墙；点击海报会直接在新标签页打开网址。

## 特点

- 纯 HTML、CSS、Vanilla JavaScript，无构建步骤、无第三方依赖
- 收藏元数据和图片 Blob 全部保存在浏览器 IndexedDB
- 支持新增、编辑、更换图片、复制链接、删除和即时搜索
- 支持建立博主档案；一个博主可以关联多个独立作品，并拥有头像、简介和主页地址
- 每个收藏可选择 3:2 或 3:4 显示比例，默认使用 3:2
- 一个收藏可以选择多张本地图片，卡片会自动柔和轮播
- 每次打开收藏都会在本地累计次数，可切换为“点击最多”排序
- 除首页外的图片卡片使用 6 槽自适应网格：桌面端一行可放 3 张 3:2 横卡或 6 张 3:4 竖卡，混排时自动补位；iPad 为 4 槽，手机为 2 槽
- 首页横向影片架按统一高度展示，3:2 横图会自动加宽并与 3:4 竖图上下对齐
- 全部收藏、分类和搜索结果共用按比例跨列的混合网格，横图和竖图不会互相撑出大块空白
- 网站分类可创建无需图片的文字网址卡片；网站收藏不进入首页或全部收藏
- 网站分类中的无图片文字卡片使用独立紧凑尺寸，不会和有图网站卡片一样铺满三分之一页面
- 分类可以拖动排序，也可用上下箭头在触屏或键盘上调整；顺序会持久保存并同步到侧栏、添加表单和首页分区
- 分类可以新增、重命名和删除；删除分类时收藏会移到“未分类”
- Mac 作为主库，可导出带 SHA-256 校验的分卷备份（`manifest.json`、`data-001.json`、`images-*.mvpart`、`checksums.json`），并在 iPad/iPhone 上完整覆盖恢复
- 图片与收藏元数据分开保存；列表先读缩略图，进入可视区域后再升级为显示图，离开后释放
- 新图片保存为最长边 1800px、质量 0.90 的 WebP，并生成最长边 480px 的缩略图；GIF 保留原格式，截图/二维码可无损保存
- 旧版内嵌 PNG 可在设置中先对比画质，再分批、可继续地迁移；旧版 v1/v2 JSON 和 v3 JSON 分卷仍可恢复
- 响应式海报墙，支持 Mac、iPad 和 iPhone

## 在 Mac 上启动

在 Terminal 中进入本项目目录：

```bash
cd /Users/lunalhx/Desktop/MV
python3 -m http.server 8000
```

然后在浏览器打开 [http://localhost:8000](http://localhost:8000)。停止服务器时回到 Terminal 按 `Control + C`。

不要直接双击 `index.html` 使用 `file://` 打开。静态服务器能让 ES Modules、IndexedDB 和 PWA manifest 更稳定地工作。

## 发布到 GitHub Pages

本项目已包含 GitHub Pages 自动发布工作流。将项目推送到 GitHub 公开仓库的 `main` 分支后，在仓库的“Settings → Pages”中把发布来源设为“GitHub Actions”；之后每次推送都会自动发布。

发布后可通过以下地址访问：

```text
https://你的用户名.github.io/仓库名/
```

不要把网站设置里导出的 `my-collection-backup-YYYY-MM-DD.json` 提交到仓库。收藏数据仍然保存在各设备浏览器本地，不会因为发布网站而同步到 GitHub。

## 添加与打开收藏

1. 点击右上角“＋ 添加”。
2. 输入标题和完整网址（以 `http://` 或 `https://` 开头）。
3. 从本机选择一张或多张 JPG、PNG、WEBP 或 GIF 图片，并选择分类。含小字、二维码或界面截图时，勾选“截图 / 二维码 / 界面”。
4. 按图片用途选择横向海报、竖版、方形或横版画面显示比例。
5. 保存后，点击图片会直接在新标签页打开网址。

照片类图片会保存为最长边 1800px 的 WebP；GIF 保留动画；勾选无损时保留 PNG。图片不会上传到任何服务器。

多张图片约每 5 秒切换一次。只有一张图片时不会启动轮播；系统开启“减少动态效果”时也会停留在第一张。编辑收藏并重新选择图片，会替换该收藏原来的整组图片。

## 管理博主与作品

1. 点击侧栏“博主”，再点击右上角“添加博主”。
2. 保存名称，并可选填头像、简介和主页地址。
3. 进入博主详情页后点击“添加作品”，新收藏会自动关联当前博主，并默认归入“博主作品”分类。
4. 也可以在普通收藏的新增或编辑表单中，通过“所属博主”更改归属。

“博主作品”不会出现在侧栏或首页分区里，作品从“博主”进入查看。设置里仍可管理这个分类。

删除博主不会删除作品，只会解除这些作品与博主的关联。博主资料与作品关系会一同写入 JSON 备份；旧版备份仍可正常导入。

首页标题区域提供“最近添加”和“点击最多”两种排序，并会记住上次选择。点击海报打开网址时，次数会保存在该收藏记录中；次数相同时仍按添加时间排列。点击次数会自动包含在 JSON 备份里。

## 本地存储与图片优化

收藏、图片和博主资料仍只保存在当前设备的浏览器中，不会上传。设置页会显示已用空间、配额、文字/显示图/缩略图占比、持久存储状态，以及最近一次备份的时间和来源设备。

旧资料库升级后不会在数据库升级步骤中删除或转换图片。先把旧版完整 JSON 保存在外接硬盘，再在 Mac 主库打开“设置 → 本地存储”，点击“优化旧图片”。应用会先抽出最多 12 张样本，对比原图、WebP 0.90 和 0.85；确认后每次处理 2–5 张图片：生成并写回校验显示图和缩略图，成功后才清除该收藏的旧内嵌 PNG；关闭页面后可以继续。新分卷备份保存浏览器使用的高质量 WebP 或无损 PNG，不代替你单独保管的原始图片文件。

## 分卷备份

1. 在 Mac 主库完成旧图片优化。
2. 打开“设置 → 备份与恢复”。
3. 点击“导出完整备份”。
4. 允许浏览器下载多个文件，并把它们放进同一个硬盘文件夹，例如：

```text
My-Collection-Backup/
├── manifest.json
├── data-001.json
├── images-001.mvpart
├── images-002.mvpart
└── checksums.json
```

浏览器下载的文件名会带日期和备份编号前缀，例如 `my-collection-backup-2026-09-14-abcd1234-images-001.mvpart`。请把同一组文件放进同一个文件夹。每个图片分卷目标大小约 45MB。清单和 `checksums.json` 包含来源设备、导出时间、文件大小和 SHA-256 校验值。文件仍包含私人标题、网址和图片，请妥善保管。

## 恢复或迁移到另一台设备

1. 通过 AirDrop、外接硬盘或 Files 把完整备份文件夹放到目标设备。
2. 在目标设备的 Safari 中打开本应用。
3. 进入“设置”，点击“完整替换恢复”。
4. 一次选择 manifest、checksums、data 和全部 `.mvpart` 文件。
5. 核对来源设备、日期和收藏数量后确认完整替换。

应用会先校验并写入临时资料库；全部成功后才切换。缺少分卷、文件损坏或写入中断时，原资料库不会被替换。完整恢复不是合并：目标设备独有的修改会被覆盖。旧版单个 v1/v2 JSON 以及 v3 JSON 分卷仍可选择恢复，但超大旧文件应先在 Mac 上恢复、优化，再导出新分卷。

## 只同步新增的几条

1. 先在 Mac 上做过至少一次「导出完整备份」。
2. 之后如果只新增或修改了少数收藏，打开设置，点击「导出变更」。
3. 把这次下载的 `my-collection-delta-...` 文件拷到 iPhone / iPad。
4. 在目标设备上点「合并变更」，一次选齐该组文件。

变更包只包含上次导出之后改过的收藏和对应图片，体积会小很多。合并时会更新这些条目，**不会删除**目标设备上多出来的收藏。打开次数按设备分别累计后再相加，完整恢复或合并变更时都会保留各端自己的次数。若在 Mac 上删除了作品，或两边改了同一条标题/图片，请仍用完整备份覆盖。

## 让同一局域网内的 iPad / iPhone 访问

先确保 Mac 和移动设备连接同一个 Wi-Fi，并保持上面的静态服务器运行。

在 Mac Terminal 查询局域网 IP：

```bash
ipconfig getifaddr en0
```

假设输出是 `192.168.1.20`，就在 iPad / iPhone Safari 打开：

```text
http://192.168.1.20:8000
```

如果打不开，请在 macOS 防火墙提示中允许 Python 接收入站连接，并确认路由器没有开启“访客网络隔离”。某些 Mac 使用有线网络或不同网卡时，`en0` 可能没有结果；可以在“系统设置 → Wi-Fi → 详细信息 → TCP/IP”查看 IP 地址。

局域网地址和 `localhost` 在浏览器看来是不同站点，各自有独立的 IndexedDB。请使用导出 / 导入迁移数据。

## 添加到 iPhone / iPad 主屏幕

在 Safari 打开应用，点击“分享”，选择“添加到主屏幕”。项目包含基础 `manifest.json` 和图标；第一版没有 Service Worker，因此离线打开前仍需 Mac 上的静态服务器可访问。

## 数据与浏览器说明

- 数据只存在于当前浏览器、当前站点地址对应的 IndexedDB 中。
- 清除网站数据、删除浏览器资料或使用无痕模式，可能导致数据消失。请定期导出备份。
- Safari 和 Chrome 不会自动同步这个应用的数据。
- 浏览器可能在存储空间紧张时清理很久未使用的网站数据；重要收藏务必保留 JSON 备份。
